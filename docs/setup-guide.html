2.4 Set Langfuse URL AUTOMATED
Updates the Langfuse NEXTAUTH_URL to match the private environment port mapping (port 3000).
cd ~/local-ai-packaged
sed -i '' 's|NEXTAUTH_URL: http://localhost:3002|NEXTAUTH_URL: http://localhost:3000|g' docker-compose.yml
The docker-compose.yml defaults to port 3002 for NEXTAUTH_URL, but the private override maps Langfuse to port 3000.

▶ Phase 3: Install Ollama & Models

0/3
3.1 Install Ollama AUTOMATED
Installs Ollama via Homebrew. If you don't have Homebrew, install it first from brew.sh or download Ollama directly from ollama.com.
# Install via Homebrew (recommended)
brew install ollama

# Or if already installed, check version:
ollama --version
✓ Should print Ollama version info
3.2 Start Ollama server AUTOMATED
Starts the Ollama server in the background. If Ollama is already running (e.g., from the macOS app), this step can be skipped.
# Start Ollama (skip if the Ollama app is already running)
ollama serve &>/dev/null &

# Verify it's responding
sleep 2
curl -s http://localhost:11434 && echo " Ollama is running!"
✓ Should print: Ollama is running!
3.3 Pull AI models AUTOMATED
Downloads the default LLM (Qwen 3.5) and embedding model (nomic-embed-text). This may take several minutes depending on your internet speed.
# Pull the default LLM (~4.7 GB)
ollama pull qwen3.5:9b

# Pull the embedding model (~274 MB)
ollama pull nomic-embed-text
✓ Both models show success after downloading
On slow connections, model downloads can take 10-20 minutes. The progress bar in the terminal shows download status.

▶ Phase 4: Launch the Stack

0/3
4.1 Run the start script AUTOMATED
This script clones Supabase, copies your .env, generates SearXNG keys, then starts all services. Uses --profile none because Ollama runs on your Mac natively (not in Docker).
cd ~/local-ai-packaged
python3 start_services.py --profile none --environment private
✓ Script completes without errors. Docker images will be pulled on first run (may take 5-15 minutes).
First run downloads ~8 GB of Docker images. The script starts Supabase first, waits 10 seconds, then starts the remaining services. You'll see extensive terminal output — this is normal.
4.2 Wait for services to become healthy AUTOMATED
Polls key services until they respond. Some services (especially Supabase and Langfuse) can take 30-60 seconds to fully start.

▶ Phase 5: Service Setup & Verify

0/6
5.1 Create n8n owner account USER ACTION
Set up the initial owner account for n8n, the workflow automation platform.
In the browser tab:
  1. You'll see the "Set up owner account" page
  2. Enter your name, email, and a password
  3. Click "Next"
  4. Skip or complete the optional survey
  5. You'll land on the n8n workflow editor — this means it worked!
This is a local-only account. It is not connected to any cloud service. Your workflows and data stay on your machine.
5.2 Create Open WebUI account & connect Ollama USER ACTION
Set up the admin account for Open WebUI (your ChatGPT-like interface) and verify the Ollama connection.
In the browser tab:
  1. Click "Sign up" to create an admin account (first user is automatically admin)
  2. Enter name, email, password, then click "Create Account"
  3. Once logged in, click your avatar (bottom-left) → "Admin Panel"
  4. Go to "Settings" → "Connections"
  5. Under Ollama, set the URL to:
    http://host.docker.internal:11434
  6. Click the refresh icon — you should see your models appear (qwen3.5:9b, nomic-embed-text)
  7. Click "Save"
The Ollama URL must be http://host.docker.internal:11434 (not localhost), because Open WebUI runs inside Docker and needs to reach your Mac's Ollama through Docker's host gateway.
5.3 Verify Qdrant vector database AUTOMATED
Checks that Qdrant (the vector database used for RAG) is running and opens its dashboard.
curl -s http://localhost:6333/healthz && echo " Qdrant is healthy!"
✓ Returns OK and the dashboard loads in the browser
5.4 Set up Neo4j USER ACTION
Log into the Neo4j graph database browser. You'll need the credentials from Step 2.3.
In the browser tab:
  1. You'll see the Neo4j Browser connect screen
  2. Connection URL should be: bolt://localhost:7687
  3. Username: neo4j
  4. Password: the password after the / in your NEO4J_AUTH value from Step 2.3
  5. Click "Connect"
  6. If prompted to change password, set a new one and save it
5.5 Set up Langfuse USER ACTION
Create an account and project in Langfuse, the LLM observability platform. Generate API keys for n8n workflow tracing.
In the browser tab:
  1. Click "Sign Up" to create a new account
  2. Enter name, email, and password, then click "Sign up"
  3. Create a new organization when prompted
  4. Create a new project (e.g., "Local AI")
  5. Go to "Settings" → "API Keys"
  6. Click "Create new API keys"
  7. Save the Public Key and Secret Key — you'll use these in n8n for tracing AI workflows
If you used 1Password in step 2.2, store the API keys in the "Langfuse" item (fields: Secret Key and Public Key). They are already wired into .env.tpl as LANGFUSE_SECRET_KEY and LANGFUSE_PUBLIC_KEY, so future ./generate-env.sh runs will inject them automatically.
5.6 Test end-to-end: chat with AI USER ACTION
The moment of truth! Send a message to your locally-running AI model through Open WebUI.
In the browser tab:
  1. Click "New Chat" (top-left)
  2. Select "qwen3.5:9b" from the model dropdown at the top
  3. Type a message like: "Hello! Can you tell me what 2+2 is?"
  4. Press Enter and wait for a response
  5. If you get a response — congratulations, your local AI stack is working!
The first message may take 10-30 seconds as the model loads into memory. Subsequent messages will be much faster.
